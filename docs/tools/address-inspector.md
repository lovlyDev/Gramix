# Локальная проверка TON-адреса

Я добавил в разработку 0.2.0 автономную проверку raw и friendly адресов. Локальная операция не делает сетевых запросов.

```text
gramix address inspect EQAs9VlT6S776tq3unJcP5Ogsj-ELLunLXuOb1EKcOQi4wJB
gramix address inspect 0:2cf55953e92efbeadab7ba725c3f93a0b23f842cbba72d7b8e6f510a70e422e3 --json
```

Проверяются длина, алфавит, CRC16, теги bounceable/testnet, workchain и 256-битный хеш. На выходе есть канонический raw, bounceable и non-bounceable варианты того же адреса. Для raw входа сеть из самого адреса определить нельзя; отображаемые friendly варианты используют флаг mainnet. Это кодировка адреса, а не доказательство существования аккаунта в сети.

Для повреждённого адреса команда возвращает ненулевой код выхода. В Desktop поле ввода и результат доступны на странице «Проверка адреса».

Отдельная кнопка «Запросить состояние аккаунта» отправляет только проверенный публичный raw адрес в OpenTonAPI. Для адреса с флагом testnet используется `testnet.tonapi.io`, иначе `tonapi.io`. Ответ помечается источником и временем получения; баланс отображается точно в nanotON. У запроса есть тайм-аут 10 секунд, ограничение ответа 64 КиБ, обработка HTTP 429 и локальный интервал между запросами. Ответ не кэшируется и не показывается как текущий после нового ввода. Rust-модуль прошёл `cargo test --lib --locked`, публичный ответ OpenTonAPI проверен отдельным HTTP-запросом. Вызов через установленный интерфейс ещё не проверен.

История с пагинацией, токены, NFT, QR-код и экспорт пока отсутствуют; Address Inspector в целом не соответствует полной приёмке 0.2.0.
